## 1. 概要

**伝書鳩**は Discord と Office Canvas を繋ぐ常駐型 Bot。えむが寝ている間も部門エージェントを Canvas 上に生き続けさせ、Discord のメッセージを Canvas に自動転送する。

### 指揮系統

```
えむ（どらどら）
  └─ フィル（司令塔チャンネル）
       └─ 伝書鳩（Bot）
            └─ 各部門チャンネル → Office Canvas
```

- **えむから部門への指示**: 司令塔チャンネルで `/relay_panel` を使う
- **外部イレギュラー**: 直接該当部門チャンネルに届く（Botが自動転送）
- **成果物の行き先**: えむ指示のもの → `📦ドラの成果物` / 部門自律のもの → `📦部門の成果物`

### 動作に必要なもの

| 要素 | 役割 |
|------|------|
| `scripts/discord_bot.py` | Bot 本体 |
| backend (port 8000) | Canvas API エンドポイント |
| frontend (port 3000) | Canvas 画面（確認用） |
| `.env` の `DISCORD_BOT_TOKEN` | Bot 認証トークン |

## 3. スラッシュコマンド一覧

### `/status`
システムステータスを embed で表示する。Bot の生死確認に使う。

表示内容: Discord Bot 状態 / Canvas API URL / Session ID / ハートビート間隔 / キャラ数 / 監視チャンネル数

### `/ask [dept] [question]`
指定部門のエージェントに質問を投げ、Canvas に転送する。

```
/ask dept:research question:DeFiの最新動向を調べて
```

`dept` には部門 ID を英語で入力する（`commander` / `research` / `sales` / `design` / `content` / `writing` / `advertising` / `ai_investment` / `new_biz` / `phil_consulting` / `real_estate` / `takumi_x` / `doradora_sns` / `origin_story` / `security`）。

### `/bridge [message]`
メッセージを Canvas ブリッジ経由で司令塔（commander）に配信する。司令塔ログチャンネルにも自動記録される。

```
/bridge 今日のタスクを全部門に共有します
```

### `/relay_panel`
**15部門中継パネル**を表示する（えむ専用の指示ツール）。司令塔チャンネルで使うのが基本。

### `/silence`
自発活動スケジューラーを一時停止する。会議や集中作業でチャンネルを静かにしたい場合に使う。停止中は定例会議も行われない。

### `/resume`
`/silence` で停止した自発活動を再開する。次の4時間サイクルから自律発言が再開される。

### `/meeting [議題]`
臨時会議を即時開催する。議題を省略した場合は shared_state.json から自動選定される。

```
/meeting 不動産部の今月目標について
```

### `/cost`
月間 API コストの使用状況を表示する。現在の累積コストと月間上限に対する残量が確認できる。

## 5. 15部門中継パネルの使い方（重要）

えむが各部門に直接指示を出すためのメインインターフェース。

### 手順

**1. 司令塔チャンネルで `/relay_panel` と打つ**

embed とボタン群が表示される。

**2. ボタンの色分け**

| 色 | 対象部門 |
|----|---------|
| blurple（紫青） | 司令塔 / セキュリティ部 |
| green（緑） | コンテンツ部 / デザイン部 / ライティング部 / リサーチ部 / 営業部 / 広告部 |
| grey（グレー） | AI投資部 / 新規事業部 / フィルコンサル部 / 不動産部 |
| red（赤） | タクミX部 / どらどらSNS部 / コピーロボット部 |

**3. 部門ボタンをクリック**

メッセージ入力モーダル（ポップアップ）が開く。

**4. メッセージを書いて送信**

送信後、以下が自動で行われる:
- 該当部門チャンネルに embed で転送
- Canvas に HMAC イベントを送信（Canvas 上のキャラに反映）
- 送信者に「転送完了」の確認メッセージが届く（本人にのみ見える）

### 注意点

- **古いパネルのボタンは動かない**。ボタンを押して「インタラクションに失敗しました」と出たら、古いパネルのメッセージを削除して `/relay_panel` で新しく作り直すこと。
- Bot 再起動後も新しいパネルのボタンは正常に動作する（永続 View 実装済み）。

## 6. 自動機能

### メッセージ自動転送
部門チャンネルに書き込まれたメッセージは Canvas に自動転送される。Bot 自身のメッセージと他の Bot のメッセージは転送されない。

### 添付ファイル対応
| ファイル種別 | Canvas への送信内容 |
|-------------|-------------------|
| 画像（png/jpg/gif/webp） | ファイル名・URL |
| PDF | ファイル名・サイズ |
| テキスト（MD/txt） | ファイル名・内容（最大 2000 字） |
| 動画（mp4/mov） | ファイル名・サイズ・URL |

### ハートビート
5分ごと（デフォルト）に全キャラを Canvas に再送信して TTL をリセットする。これにより Canvas からキャラが消えなくなる。

### チャンネル・カテゴリ自動作成
Bot 起動時に `CATEGORY_STRUCTURE` の定義に従ってカテゴリとチャンネルを自動整理する。冪等（何度実行しても同じ結果）。

### サーバー名自動設定
Bot 起動時にサーバー名を「ミスターDオフィス」に変更する。既に正しい名前なら何もしない。

### 自発活動スケジューラー

Bot が起動している間、4時間おきに15部門のエージェントが順番に自律発言を行う。人間からの指示がなくても各部門の活動ログが Discord に蓄積される。

動作の流れ:

1. 4時間ごとにスケジューラーが起動
2. 15部門を順番に呼び出し（部門ごとに間隔をあけて送信）
3. 各部門が担当チャンネルに自律発言を投稿
4. 発言内容は shared_state.json の状態を参照して生成

`/silence` で一時停止、`/resume` で再開できる。

### 定例会議

毎日 14:00 JST に自動で開催される。会議室チャンネルに議事録が記録される。

| 項目 | 内容 |
|------|------|
| 開催時刻 | 毎日 14:00 JST |
| 場所 | 会議室チャンネル |
| 議題 | shared_state.json のステータスと進行中タスクから自動選定 |
| 進行 | 3ラウンド形式（課題提起 → 議論 → アクション決定） |
| 司会 | フィル（commander）が自動担当 |

`/meeting [議題]` で任意のタイミングに臨時会議を開催できる。

### shared_state.json 自動書き戻し

Discord での活動（部門発言・会議決定・成果物生成）は自動的に shared_state.json に反映される。他のセッションや Claude Code チャットがshared_stateを読めば、Discord 上で何が行われたかを把握できる。

### 成果物自動保管

部門が成果物を生成した場合、「📦部門の成果物」チャンネルに Markdown ファイルとして自動保存される。

- えむが指示して生成したもの: 「📦ドラの成果物」チャンネル
- 部門が自律的に生成したもの: 「📦部門の成果物」チャンネル

## 7. Office Canvas 連携

### 仕組み
```
Discord メッセージ
  → 伝書鳩（Bot）
    → HMAC 署名付き POST
      → backend (port 8000) /api/v1/external_event
        → WebSocket
          → frontend (port 3000) Canvas 画面
```

### Canvas 上の表示
- 各部門キャラが Canvas のデスクに表示される
- メッセージが届くとキャラのステータスが変わる
- DiscordTicker（Canvas 画面の下部スクロール帯）に最新メッセージが流れる

### Canvas 接続確認
Bot 起動ログに「Canvas announce: N OK, 0 failed」と出ていれば正常。`failed` が多い場合は backend が起動していない。

## 9. トラブルシューティング

### 「インタラクションに失敗しました」と出る
古いパネルのボタンを押した時に発生する。Bot 再起動前に作ったパネルが残っている場合に起きる。

**対処**: 古いパネルのメッセージを削除して、`/relay_panel` で新しく作り直す。

### ボタンを押しても何も起きない
Bot が停止している可能性がある。

**対処**: `ps aux | grep discord_bot` でプロセスを確認。起動していなければ再起動する。

### Canvas にキャラが出ない
backend と frontend の両方が起動している必要がある。

**対処**:
1. backend: `http://localhost:8000/api/v1/external_event` が応答するか確認
2. frontend: `http://localhost:3000` にアクセスできるか確認
3. ログに「Canvas announce: 0 OK, N failed」と出ていたら backend が起動していない

### Bot がログインできない
**対処**: `.env` の `DISCORD_BOT_TOKEN` が正しいか確認。Discord Developer Portal で Bot Token を再発行する。

### MESSAGE CONTENT インテントエラー
**対処**: Discord Developer Portal > Bot > Privileged Gateway Intents > MESSAGE CONTENT INTENT を ON にする。

### 部門チャンネルのメッセージが Canvas に届かない
Bot がそのチャンネルを監視しているか確認する。`部門一覧` コマンドで確認できる。

### Bot が応答しない（一般的な確認手順）

まずログを確認する。

```bash
tail -50 /tmp/claude_office_bot.log
```

ログに `ERROR` が出ていればその内容で原因を特定できる。ログファイルがない場合は Bot が起動すらしていない。

### API エラーが出る

`.env` の `ANTHROPIC_API_KEY` を確認し、[Anthropic Console](https://console.anthropic.com) でクレジット残高を確認する。残高がゼロの場合は API 呼び出しが全て失敗する。

### 月間コスト上限に達した

`/cost` でコスト状況を確認し、`config/autonomous_office.json` の `monthly_cost_cap_usd` の値を引き上げる。

```json
{
  "monthly_cost_cap_usd": 30
}
```

上限を上げた後、Bot を再起動すると反映される。

### プロセスが途中で落ちた

```bash
# 残存プロセスを終了
pkill -f discord_bot.py

# 再起動
python3 scripts/discord_bot.py
```

## 11. コスト管理

### モデル別料金

| モデル | 入力 | 出力 | 使用部門 |
|--------|------|------|---------|
| Claude Sonnet 4 | $3 / 1M トークン | $15 / 1M トークン | 12部門（主力） |
| Claude Opus | $15 / 1M トークン | $75 / 1M トークン | commander のみ |
| Claude Haiku | $0.25 / 1M トークン | $1.25 / 1M トークン | security / origin_story |

### 想定コスト目安

| 単位 | 内容 | 概算 |
|------|------|------|
| 1サイクル | 15部門が1回ずつ発言 | 約 $0.10 |
| 1日 | 4時間おき 6サイクル + 定例会議1回 | 約 $0.60 〜 $0.80 |
| 1ヶ月 | 上記の30日分 | 約 $18 〜 $24 |

### 月間上限設定

デフォルトの月間上限は $30。`config/autonomous_office.json` で変更できる。

```json
{
  "monthly_cost_cap_usd": 30,
  "cycle_interval_hours": 4,
  "daily_meeting_time_jst": "14:00"
}
```

上限に達すると自発活動が自動停止し、Discord の司令塔チャンネルに通知が届く。`/cost` でいつでも現在の使用状況を確認できる。

### コスト削減のヒント

- haiku モデルで対応できる部門（security / origin_story）はすでに haiku に設定済み
- `/silence` で自発活動を止めると1日あたり約 $0.60 を節約できる
- 使用頻度の低い部門を発言サイクルから外す場合は `config/autonomous_office.json` の `active_depts` リストを編集する
