# 自律オフィス — 要件定義

> 生成日: 2026-04-22
> スペック: autonomous-office
> バージョン: 1.0

## 背景

ミスターDオフィスのDiscordサーバーには15部門のチャンネルがあるが、
現状は「えむが送る → 届く → 終わり」の一方通行。
部門AIが自分で考えて返事し、アイデアを出し、成果物を作る仕組みが必要。

えむの言葉: 「俺の指示関係なく、そこにはたくさん事業部の人間がいるんだからさ、いいアイデアが浮かぶと思っていて。」

## ゴール

えむが指示しなくても部門が自律的に動き、アイデアが生まれ、成果物が蓄積するオフィス。

---

## REQ-001: 部門AI返答

**概要**: 部門チャンネルにメッセージが届いたら、その部門のAIキャラが返事する。

**詳細**:
- リレーパネル経由 or 直接投稿でメッセージが来たら、部門AIが読んで返答する
- 返答は部門キャラの名前・色・アイコンでembedとして投稿される
- 返答はCanvasにもASK_COMPLETEDイベントとして送信される
- 各部門には固有のシステムプロンプト（性格・専門知識・口調）がある
- 会話コンテキスト: チャンネルの直近5件のメッセージを参照する

**受け入れ条件**:
- [ ] リレーパネルから「こんにちは」→ 部門AIが返事する
- [ ] 返事が部門キャラのembed形式でチャンネルに投稿される
- [ ] Canvasに返答イベントが反映される
- [ ] 各部門で異なる性格・口調の返答が返る
- [ ] Bot自身のメッセージには反応しない（無限ループ防止）

---

## REQ-002: 部門自発活動

**概要**: 部門AIが定期的に自分から発言する（朝会報告・気づき・提案）。

**詳細**:
- 各部門は設定された間隔（デフォルト: 4時間）で自発的に発言する
- 発言タイプ: 朝会報告 / アイデア提案 / 他部門への質問 / 進捗報告
- 発言内容は部門の専門領域に基づいてAIが生成する
- 自発活動のスケジュールは設定で変更可能
- えむの就寝時間帯（0:00-7:00 JST）は静音モード

**受け入れ条件**:
- [ ] 部門が4時間ごとに自発的にチャンネルに投稿する
- [ ] 投稿内容が部門の専門領域に沿っている
- [ ] 深夜0時〜朝7時は投稿されない
- [ ] Canvasに自発活動イベントが反映される
- [ ] `/silence` コマンドで一時停止できる

---

## REQ-003: 会議室ディスカッション

**概要**: 会議室チャンネルで複数部門AIが議論する。

**詳細**:
- えむが議題を投稿 or `/meeting [議題]` コマンドで開始
- 関連する3-5部門が自動選択される（議題のキーワードから判定）
- ターン制: 各部門が1回ずつ発言 × 3ラウンド
- 最後に司令塔（フィル）がまとめを投稿
- 会議結果はCanvasにも反映

**受け入れ条件**:
- [ ] `/meeting AI投資の方向性` で3-5部門が議論を開始する
- [ ] 各部門が順番に発言する（1部門ずつ、間に3秒の間隔）
- [ ] 3ラウンド後にフィルがまとめを投稿する
- [ ] まとめがCanvasに反映される
- [ ] 会議中は他の自発活動が一時停止する

---

## REQ-004: 成果物自動保管

**概要**: 部門が生成した成果物を📦チャンネルに自動保管する。

**詳細**:
- 部門AIの返答が「成果物」と判定された場合、📦チャンネルにコピーする
- 成果物の判定: ファイル添付 / 10行以上のコードブロック / レポート形式 / 明示的な「成果物:」タグ
- えむが依頼した結果 → 📦ドラの成果物
- 部門自律の結果 → 📦部門の成果物
- 保管時にサマリーembed（元チャンネルへのリンク付き）を作成

**受け入れ条件**:
- [ ] 部門AIが長文レポートを投稿 → 📦部門の成果物にサマリー+リンクが自動投稿
- [ ] リレーパネル経由の依頼結果 → 📦ドラの成果物に保管
- [ ] 保管embedに元メッセージへのジャンプリンクが含まれる
- [ ] 同一成果物の重複保管が起きない

---

## REQ-005: 取り扱い説明書

**概要**: Discord + Office Canvasの使い方ガイドをHTMLで生成する。

**詳細**:
- サーバー構成（6カテゴリ・全チャンネル）
- スラッシュコマンド一覧と使い方
- リレーパネルの使い方
- 部門AI返答の仕組み
- 会議室の使い方
- 成果物保管の仕組み
- トラブルシューティング

**受け入れ条件**:
- [ ] MD + HTML の両方が生成される
- [ ] デスクトップ司令塔本部フォルダに保存される
- [ ] 全コマンド・全機能が網羅されている

---

## REQ-006: 開発テストチェックリスト

**概要**: 開発者（AI）が毎回必ず実行するテスト手順の雛形。

**詳細**:
- Phase 1: コードレビュー（構文・型・Codex）
- Phase 2: バックエンド（Bot起動・ログ確認・Canvas接続）
- Phase 3: 表側テスト（Canvas画面・Discord画面・ボタン動作・メッセージ転送）
- Phase 4: 完了報告テンプレート（証拠付き）
- Phase 3をスキップして「OK」と言うこと禁止

**受け入れ条件**:
- [ ] チェックリストがMDファイルとして存在する
- [ ] 全項目にチェックボックスがある
- [ ] 完了報告テンプレートが含まれている

## 非機能要件

### コスト管理
- NFR-001: 部門返答は claude-sonnet を使用（1返答 ≈ $0.003）
- NFR-002: 自発活動は1日最大6回/部門（15部門 × 6回 = 90回/日 ≈ $0.27/日）
- NFR-003: 会議は1回あたり最大20 API呼び出し（$0.06/会議）
- NFR-004: 月間コスト上限: $30（超えたら自発活動を停止）

### パフォーマンス
- NFR-005: 返答は10秒以内に投稿される
- NFR-006: 会議の1ターンは5秒以内
- NFR-007: Canvas反映は返答投稿の1秒以内

### 安全性
- NFR-008: Bot自身のメッセージには絶対に反応しない（無限ループ防止）
- NFR-009: 1分間の最大API呼び出し数: 10回（レートリミット）
- NFR-010: APIエラー時はリトライ1回、それでも失敗ならスキップしてログ記録
