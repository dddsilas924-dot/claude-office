# Discord安全設計ルール（絶対遵守）

## 核心原則

**Discordはホワイトボード（アイデアの場）。Claude Codeは正式な記録。**

AI同士が出した結論・自発活動の提案・会議の議事録は、
Discord内で完結させる。Claude Code側のmemory・shared_state・gitには
**ドラが許可しない限り入れない。**

---

## 境界ルール

### Discord → Claude Code に自動で流してはいけないもの
- AI自発活動の発言内容
- AI同士の会議の結論・アクションアイテム
- 部門間依頼のやりとり
- AIが生成した任意のテキスト

### Claude Code側に入れていいもの
- ドラが「これ採用」「これ記録して」と明示的に言ったもの
- ドラが `/run` で明示的に実行指示したタスクの結果
- ドラが `/approve` で承認したタスクの結果

---

## 実行権限

| トリガー | claude -p実行 | 備考 |
|---|---|---|
| ドラが `/run` で指示 | 自動実行（safe判定時） | ドラ本人の意思 |
| ドラが `/approve` で承認 | 実行 | ドラがキューから選んだ |
| AIが自発活動で `[実行依頼:]` | **承認キューに入るだけ** | 自動実行しない |
| AIが会議で `[アクション:]` | **承認キューに入るだけ** | 自動実行しない |

---

## memory_bridge

**無効化済み。** Discord上の会話をClaude Code側のmemoryに自動保存しない。

理由:
- AIの返答にはハルシネーション（捏造）が含まれる可能性がある
- 自動保存すると嘘が「事実」としてmemoryに記録される
- 次のClaude Codeセッションでその嘘を前提に判断してしまう

代替手段:
- ドラがClaude Codeセッションで「さっきDiscordでリョウがこう言ってた、記録して」と自分の言葉で伝える
- ドラのフィルターを通ってるから信用できる

---

## なぜこのルールが必要か

AIが人間のチェックなしに生成したテキストは全て「未検証」。
Claude Codeセッションではドラがその場にいて嘘を指摘できるが、
Discordの自発活動・会議ではドラが関与していない。

**信用できるかどうかはモデルの違いではなく、ドラが関与しているかどうか。**

---

## 成果物について

AIが成果物を作ること自体はOK。
ただし「作る」と「正式に記録する」は別。

- Discord上で成果物が提案される → OK（ホワイトボードに書いてるだけ）
- ドラが見て「これいい」→ `/approve` → claude -p実行 → 成果物が生まれる → OK
- AIが勝手に成果物を作ってmemory/gitに入れる → **NG**
